# Data-Convergence Mapping

Who ends up HOLDING which datasets across nominally-separate programs? The
per-program privacy story can be clean while the convergence is the product:
entities positioned at junctions where separately-collected datasets become
joinable (shared vendors, shared identity infrastructure, acquisition of
data-rich failures, "partnerships" whose consideration is access).

## Protocol

1. List the programs/products touching the population of interest; 2. per
program: data collected, processors, retention, sharing clauses; 3. build the
CONVERGENCE table — dataset × holder — and mark junction entities (holders
appearing in ≥2 rows); 4. for each junction: what becomes inferable from the
JOIN that no single program admits collecting (*fictional junction: a transit
authority's fare-card app (location + payment) and a separate municipal
"smart streetlight" pilot (device MAC addresses) both contract the same
analytics vendor, "Lumen Grid", for "anonymized mobility insights". Neither
program admits tracking individuals — but Lumen Grid holds both feeds, and a
MAC seen at a fare gate joins them, reconstructing per-person movement neither
program collects alone. The junction, not either program, is where the
capability lives*); 5. verdicts stay with evidence: convergence capacity is an
observation; intent to converge is an attribution (kernel-shell discipline).
